# Skeleton

Браузерная песочница в духе Valheim: процедурный мир из seed. Пока игра одиночная, кооператив через авторитетный
сервер — на потом, но код к нему уже готов.

Демо (одиночная игра): https://it1ro.github.io/skeleton/

## Запуск

```bash
npm install
npm run dev        # клиент (http://localhost:5173), одиночная игра, сервер не нужен
```

Seed мира задаётся в адресе: http://localhost:5173/?seed=42.

Кооператив: `npm run dev:online` запускает ещё и сервер (ws://localhost:8787/ws). Откройте
http://localhost:5173/?online в двух вкладках или на двух компьютерах в одной сети
(`npm run dev -w @skeleton/client -- --host`). Seed сервера задаётся переменной окружения: `SEED=42 npm run dev:online`.

Управление: WASD — ходьба, Shift — бег, Space — прыжок, мышь — камера, колесо — зум, P — пиксельный режим,
E — говорить, Esc — меню.

Перед коммитом: `npm run typecheck && npm test`.

Пересборка героя и анимаций из исходников: `npm run assets` (исходники — см. `assets-src/README.md`).

## NPC-спайк

У спавна стоит Повитуха — фигура из примитивов. Подойди и нажми E: свободный текст, она торгуется,
ловит ложь и даёт испытание. Правила разговора и состояние — в `packages/shared/src/npc`, всё сериализуемо.

По умолчанию реплики авторские, игра работает без сети и без модели. Чтобы включить модель:

```bash
ollama pull qwen2.5:3b
npm run npc:proxy
# открыть http://localhost:5173/?npc=llm
```

Ключ к облачной модели кладётся в `.env.npc` в корне (файл в `.gitignore`, права `600`); переменные окружения
перекрывают его. Прокси — OpenAI-совместимый, настраивается через `NPC_LLM_URL`, `NPC_MODEL`, `NPC_LLM_KEY`,
`NPC_PRICE_IN` / `NPC_PRICE_OUT` (доллары за 1M токенов), `NPC_MAX_TOKENS` и `NPC_REASONING=off` для моделей,
которые тратят весь лимит на размышления. Если ключ есть, проще поднять прокси и клиент одной командой:

```bash
npm run dev:npc   # прокси :8788 и клиент :5173
```

Модель только переозвучивает реплику, смысл и состояние сделки остаются за правилами; без прокси клиент берёт
авторскую реплику. Разбор свободного текста на действия пока правилами, не моделью.

Прототип нужен, чтобы пощупать цену и задержку: реплика приходит потоком, и под ней видно два числа —
когда появилась первая фраза и когда договорила, — а ещё токены и цену; в шапке средняя задержка и сумма
за разговор. `npm run npc:bench` проигрывает скриптованный разговор три раза и печатает p50/p95, токены
и цену.

## Голос Повитухи

Реплики звучат: текст режется на фразы по мере генерации, каждая фраза сразу уходит в синтез, а плеер
ставит их встык — первая звучит, пока остальные ещё делаются. Открытая панель сразу говорит вступительную
реплику: она известна до всякой модели и заодно греет соединение.

```bash
npm run dev:npc                       # модель + голос + клиент
INWORLD_API_KEY=... npm run npc:proxy # только прокси, ключ можно положить в .env.npc
```

Голос — Inworld TTS. Модель и голос задаются `INWORLD_TTS_MODEL` (по умолчанию `inworld-tts-2`, для скорости
и цены есть `inworld-tts-2-flash`), `INWORLD_TTS_VOICE` и `INWORLD_TTS_RATE`. Дальше: `INWORLD_TTS_DELIVERY`
(`STABLE` / `BALANCED` / `CREATIVE`; flash это поле игнорирует), `INWORLD_TTS_LANGUAGE` (по умолчанию `ru-RU` —
включает русский голосовой промпт), `INWORLD_TTS_CHARACTER` и `INWORLD_TTS_REASONING` — steering: модель читает
фразу и сама решает, как её подать (живее, но примерно на секунду медленнее).

Голос из описания (`INWORLD_TTS_DESIGN`) — режим предпросмотра: каждый запрос создаёт **новый** голос, поэтому
для персонажа его лучше один раз спроектировать и опубликовать через `POST /voices/v1/voices:design` →
`POST /voices/v1/voices/{voiceId}:publish`, а в конфиг положить полученный `voiceId`. Так характер голоса
не меняется от реплики к реплике.

В синтез уходят и предыдущие реплики: голос слышит разговор, а не отдельную фразу. Ключ живёт только в прокси,
браузер его не видит. Без ключа игра просто молчит. Синтезированные фразы кэшируются на диске прокси
(`.cache/tts`, общий для всех игроков) и в IndexedDB браузера, поэтому повторные реплики звучат мгновенно
и не стоят денег; если синтез упал — реплика остаётся текстом.

## Стек

- TypeScript везде, npm workspaces.
- Клиент: three.js `WebGPURenderer` (WebGPU, если есть, иначе WebGL2), Vite.
- Сервер: Node + `ws`, запуск через `tsx`.
- Тесты: Vitest.

## Как это устроено

**Мир из seed.** `createTerrain(seed)` в `shared/src/terrain.ts` — чистые функции: высота, биом, деревья в чанке.
Сервер и все клиенты строят один и тот же мир. Сохранять и передавать по сети нужно только изменения игроков
(срубленное дерево, выкопанная яма, постройка), а не сам мир.

**Ландшафт.** Карта высот, как в Valheim, а не воксели. Чанки 64×64 м строятся в Web Workers
(`client/src/world/terrain.worker.ts`) и подгружаются вокруг игрока. Деревья — `InstancedMesh`, по два вызова отрисовки на чанк.

**Симуляция.** Игра устроена как клиент и авторитетный сервер даже в одиночной игре. Симуляция
(`createSim` в `shared/src/sim.ts`) работает с фиксированным шагом 30 Гц, хранит игроков и считает движение
(`stepPlayer` в `shared/src/movement.ts`). Сети она не знает. В одиночной игре она крутится в самой вкладке
(`connectLocal` в `client/src/net/connection.ts`), в коопе — на сервере за WebSocket (`connectServer`).
Сообщения в обоих случаях одни и те же. Правила — в «Правилах симуляции» ниже.

**Сеть.** Клиент отправляет только ввод. Свой игрок двигается сразу (предсказание), по снимку сервера клиент откатывается
и переигрывает неподтверждённый ввод (`client/src/player/local.ts`). Чужие игроки рисуются с задержкой ~130 мс
и интерполяцией между снимками. Протокол пока JSON (`shared/src/protocol.ts`), бинарный формат — когда вырастут снимки.

**Время суток** считается из тика симуляции, поэтому у всех игроков одно время.

**Герой и анимации.** Модель (`player.glb`) и анимации (`anims_humanoid.glb`) лежат в разных файлах на одном
скелете Quaternius UAL. Сборка подгоняет кости UAL под модель героя и считает веса вершин. Аниматор (`client/src/world/animator.ts`) выбирает клип по состоянию: на земле, в воздухе
или в воде. Это состояние считается из позиции (`moveMode` в `shared`), поэтому чужие игроки анимируются так же,
как свой.

**Пиксельный вид.** Рендер в половинном разрешении и масштабирование без сглаживания (`image-rendering: pixelated`).
Клавиша P переключает.

## Правила симуляции

Код пишем так, чтобы кооп включался без переделки игры:

- **Симуляция отдельно от клиента.** Мир, игроки, враги и правила живут в `shared`. Рендер, звук и интерфейс
  только читают её состояние и не меняют его напрямую.
- **Ввод — это команды.** Клиент отдаёт симуляции команды игрока (движение, удар, постройка), а не правит
  состояние сам. В одиночной игре команды идут в симуляцию во вкладке, в коопе — на сервер.
- **Фиксированный тик.** Симуляция шагает с постоянным шагом 30 Гц, время суток и календарь считаются из тика.
- **Состояние сериализуемо.** Состояние мира и игроков — простые данные без ссылок на объекты рендера. Его же
  пишем в сохранение и рассылаем в снимках.
- **Несколько игроков с первого дня.** Симуляция хранит игроков списком с идентификаторами, даже если игрок один.
- **Случайность из seed.** Мир и события зависят от seed и тика, а не от глобального генератора.

## Минималка и эталон

Минималка и эталон производительности — **GTX 860M на aio** (2 ГБ, 2014). Тесты и запуск игры по умолчанию
делаем на ней; числа с tpad и с Intel — не эталон и с этими не сравниваются.

```bash
npm run bench:aio
```

Скрипт собирает клиент, копирует `packages/client/dist` на aio, поднимает там HTTP-сервер и headless Chrome
через `prime-run` (PRIME render offload на GTX 860M), открывает `?bench` с фиксированной камерой, греет 2 с,
мерит 10 с и пишет JSON и скриншот в `bench-results/`. По умолчанию кадры не ограничены vsync, чтобы видеть
запас над целью 60 fps; `--vsync` включает ограничение, `--min-fps 60` валит прогон ниже порога.

Нужны ssh на aio, `prime-run`, Chrome, `python3` и `systemd-run --user`. Если обычный ssh не работает, укажите
конфиг: `npm run bench:aio -- --ssh-config ~/.ssh/config-aio`. Хост, порты и бинарники перекрываются
`BENCH_HOST`, `BENCH_HTTP_PORT`, `BENCH_CDP_PORT`, `BENCH_CHROME`, `BENCH_PRIME_RUN`.

| Дата | Коммит | Сцена | fps | p95 | Backend | Разрешение |
| --- | --- | --- | --- | --- | --- | --- |
| 2026-11-05 | `9a03e6f` | спавн, до лугов | 278.8 | 3.9 мс | WebGL2 | 1280×720, пиксели 0.5 |
| 2026-11-05 | `33faac8` | луга v1 + Повитуха | 146.2 | 6.7 мс | WebGL2 | 1280×720, пиксели 0.5 |

`fps` — среднее за 10 с без ограничения кадра, `p95` — медленный хвост. Цель — 60 fps, то есть p95 ниже 16.6 мс.
Среднее шумит из-за редких провалов, p95 устойчивее: луга и Повитуха подняли его с 3.9 до 6.7 мс, запас до цели
ещё больше двух раз. Один провал 251 мс в первом прогоне — загрузка/GC; смотрим на p95, а не на среднее.

### Движущийся прогон

Стоячая сцена не грузит чанки и траву, поэтому рывки в движении видно только отдельным прогоном:

```bash
npm run bench:aio -- --run --seconds 20
```

Игрок автоматически бежит вперёд; в отчёт попадают p95, max и все постройки главного потока дольше 8 мс.

| Прогон | fps | p50 | p95 | max | Чанки |
| --- | --- | --- | --- | --- | --- |
| до фикса | 87.1 | 6.6 | 8.3 | 1817.8 | 156 |
| после | 82.1 | 6.1 | 12.2 | 884.8 | 175 |

До фикса новые тайлы травы (16 м) и чанки (64 м) строились пачкой в одном кадре. После — трава по бюджету
4 мс/кадр, чанки по одному за кадр, высота для биома считается один раз. max упал вдвое; p95 вырос, но остался
ниже 16.6 мс, то есть в бюджете 60 fps. Остаток max (884 мс) — не постройки: в лог не попало ни одной постройки
дольше 8 мс; это отдельный GC/GPU-провал, следующий шаг.

Графика — по правилу 20/80: сначала большие формы, свет и земля, потом полировка критичных мест;
см. `docs/graphics.md`.

Телеметрия — локально на aio (TimescaleDB + Grafana): `telemetry/README.md`; включается `?telemetry`.

## Продакшен

`npm run build` собирает клиент в `packages/client/dist`. Для одиночной игры хватает статики.

GitHub Pages: `.github/workflows/pages.yml` на каждый пуш в `main` проверяет код (typecheck, тесты) и выкладывает
клиент на https://it1ro.github.io/skeleton/. На pull request тот же workflow только проверяет. Кооп на Pages не
работает: там нет сервера.

Сервер для коопа запускается командой `npm run server`. Клиент с `?online` ищет сервер на своём же адресе по пути `/ws`. Обратный прокси (Caddy, nginx) должен отдавать
статику из `dist` и проксировать `/ws` на порт 8787 с поддержкой WebSocket.
