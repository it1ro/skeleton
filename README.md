# Skeleton

Браузерная песочница в духе Valheim: процедурный мир из seed, кооператив через авторитетный сервер.

## Запуск

```bash
npm install
npm run dev        # сервер (ws://localhost:8787/ws) + клиент (http://localhost:5173)
```

Откройте http://localhost:5173 в двух вкладках или на двух компьютерах в одной сети
(`npm run dev -w @skeleton/client -- --host`). Seed мира задаётся переменной окружения: `SEED=42 npm run dev`.

Управление: WASD — ходьба, Shift — бег, Space — прыжок, мышь — камера, колесо — зум, P — пиксельный режим, Esc — меню.

Перед коммитом: `npm run typecheck && npm test`.

Пересборка моделей и анимаций из исходных паков: `npm run assets` (паки — см. `assets-src/README.md`).

## Стек

- TypeScript везде, npm workspaces.
- Клиент: three.js `WebGPURenderer` (WebGPU, если есть, иначе WebGL2), Vite.
- Сервер: Node + `ws`, запуск через `tsx`.
- Тесты: Vitest.

## Структура

```
packages/
  shared/   код, общий для клиента и сервера: генерация мира, движение, протокол
  server/   авторитетный сервер: принимает ввод, считает движение, рассылает снимки
  client/   рендер, ввод, предсказание, стриминг чанков
scripts/
  build-assets.ts  сборка .glb героя и анимаций из паков Quaternius
assets-src/        исходные паки (в git не входят)
docs/
  assets.md   скелет, анимации, экспорт из Blender
  design.md   геймдизайн: тело как прогрессия
  roadmap.md  этапы до первой играбельной версии
```

## Как это устроено

**Мир из seed.** `createTerrain(seed)` в `shared/src/terrain.ts` — чистые функции: высота, биом, деревья в чанке.
Сервер и все клиенты строят один и тот же мир. Сохранять и передавать по сети нужно только изменения игроков
(срубленное дерево, выкопанная яма, постройка), а не сам мир.

**Ландшафт.** Карта высот, как в Valheim, а не воксели. Чанки 64×64 м строятся в Web Workers
(`client/src/world/terrain.worker.ts`) и подгружаются вокруг игрока. Деревья — `InstancedMesh`, по два вызова отрисовки на чанк.

**Сеть.** Сервер работает с фиксированным шагом 30 Гц и считает движение сам (`stepPlayer` в `shared/src/movement.ts`).
Клиент отправляет только ввод. Свой игрок двигается сразу (предсказание), по снимку сервера клиент откатывается
и переигрывает неподтверждённый ввод (`client/src/player/local.ts`). Чужие игроки рисуются с задержкой ~130 мс
и интерполяцией между снимками. Протокол пока JSON (`shared/src/protocol.ts`), бинарный формат — когда вырастут снимки.

**Время суток** считается из тика сервера, поэтому у всех игроков одно время.

**Герой и анимации.** Модель (`player.glb`) и анимации (`anims_humanoid.glb`) лежат в разных файлах на одном
скелете Quaternius UAL. Аниматор (`client/src/world/animator.ts`) выбирает клип по состоянию: на земле, в воздухе
или в воде. Это состояние считается из позиции (`moveMode` в `shared`), поэтому чужие игроки анимируются так же,
как свой.

**Пиксельный вид.** Рендер в половинном разрешении и масштабирование без сглаживания (`image-rendering: pixelated`).
Клавиша P переключает.

## Продакшен

`npm run build` собирает клиент в `packages/client/dist`. Сервер запускается командой `npm run server`.
Клиент ищет сервер на своём же адресе по пути `/ws`. Обратный прокси (Caddy, nginx) должен отдавать
статику из `dist` и проксировать `/ws` на порт 8787 с поддержкой WebSocket.
